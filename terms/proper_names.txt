# terms/proper_names.txt — proper-name ledger for the IME wordlist (#T-5110)
#
# Why this file exists
# --------------------
# `artifacts/domain_terms.txt` is an IME (Fcitx/Rime) word list: it must only
# contain strings a Chinese input method can actually compose. Organization /
# company / facility names are typically Latin acronyms or multi-word English
# phrases, and registry `preferred_zh` names for companies are often literal
# translations nobody types. They therefore belong to the *registry* (concept
# identity, export artifacts) and not to the IME word list.
#
# Semantics
# ---------
#   EXCLUDE_FROM_IME  exact whole-string matches removed by
#                     `pipeline.build_terms` (deny/synonyms normalisation runs
#                     first, so a synonym alias cannot smuggle an excluded
#                     string back in). Multi-word entries are inert here because
#                     the word list forbids whitespace, but they are listed so
#                     the ledger stays a complete mirror of the registry.
#   ALLOW_IN_IME      curated exemptions: kept in the word list on purpose.
#                     Each line must state the reason; the gate verifies that the
#                     string is still backed by terms/allowlist_{zh,en}.txt and
#                     still present in the built word list.
#
# Format: `<term>\t<reason>` (one entry per line; `#` lines are comments).
# Every registry `preferred_zh` / `preferred_en` of a proper-name concept
# (category in company/organization/facility) MUST appear exactly once, in one
# of the two sections. That invariant is enforced by
# `scripts/check_proper_names_ledger.py` (wired into `pipeline.release_pack`).
#
# Provenance note: the 12 pre-existing strings that motivated this file were
# introduced by bulk alias syncs (`5f3a808`, 2026-03-19; `d0bfe48`, 2026-04-04),
# not by case-by-case editorial review.
